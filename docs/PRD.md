# 私有护理题库系统 · PRD

- **项目**：private-tiku
- **技术栈建议**：Vite + React + MUI + Tailwind CSS；后端建议 Python/FastAPI + SQLite（FTS5），Docker 部署（待架构师定）
- **原始需求**：把护理试题文档（DOCX/TXT/PDF）变成可快速搜索答案的私有题库；自动识别题号/题干/选项/答案/题型；支持全文搜索；标记缺答案、格式异常题目；支持 Docker 私有化部署。

## 1. 产品目标

把散乱的护理试题文档变成可秒级检索、可校对异常的私有题库，数据不出内网。

## 2. 用户故事

1. 作为护理教研老师，我想批量导入 DOCX/TXT/PDF，以便一次性建库，无需逐题手工录入。
2. 作为备考学生，我想按题干/选项/答案/解析关键词搜索，以便几秒内定位题目与答案。
3. 作为题库管理员，我想看到缺答案、缺选项、题号重复、无题干的异常清单，以便批量校对修正。
4. 作为运维人员，我想用 Docker 一键部署到内网服务器，以便数据不依赖公网。
5. 作为教研老师，我想在入库前预览解析结果，以便拦截脏数据。

## 3. 需求池

### P0（必须）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P0-1 | DOCX/TXT/PDF 批量导入（多选/拖拽） | 单次 ≥20 文件；有进度提示；失败文件单独列出并说明原因 |
| P0-2 | 自动解析：题号、题干、选项、答案、题型 | 单选/多选/判断三种题型；人工抽样 100 题解析准确率 ≥90% |
| P0-3 | 全文搜索：题干/选项/答案/解析，多关键词组合，结果高亮 | 万级题量下查询 <1s；命中词高亮；支持空格分词组合 |
| P0-4 | 异常标记：缺答案、缺选项、题号重复、无题干 | 每题可挂多个异常标签；异常页可筛选、逐题校对、标记已处理 |
| P0-5 | Docker 部署 | `docker compose up -d` 一键启动；数据持久化到卷 |

### P1（应该）

| 编号 | 需求 |
|---|---|
| P1-1 | 解析结果预览 + 人工确认（整批确认 / 单题修改后再入库） |
| P1-2 | 题目详情页：查看与编辑题干、选项、答案、解析、题型、来源文档 |
| P1-3 | 导入统计：按文档维度展示成功/失败/异常题数，便于溯源 |
| P1-4 | 搜索二次筛选：按题型、是否异常、来源文档过滤 |
| P1-5 | 题库导出（JSON/结构化文档），便于备份迁移 |

### P2（可选）

| 编号 | 需求 |
|---|---|
| P2-1 | 分类/标签（科目、章节、难度） |
| P2-2 | 两级角色权限（管理员/普通用户） |
| P2-3 | 收藏与错题本 |
| P2-4 | 扫描件 PDF 的 OCR（默认不做，先支持文本型 PDF） |
| P2-5 | 批量删除 / 合并重复题 |

## 5. 待确认问题

1. **题库规模**：千级/万级/十万级？决定检索方案（SQLite FTS5 / PostgreSQL 全文 还是 Elasticsearch/Meilisearch）。
2. **答案形态**：答案是否只有字母？是否含判断题对错符号、多选多字母、解析文本？是否允许"无答案但有解析"的题？
3. **文档边界**：PDF 是否需 OCR 扫描件？TXT 是否需自动识别 GBK/UTF-8 编码？直接决定解析依赖与工作量。
